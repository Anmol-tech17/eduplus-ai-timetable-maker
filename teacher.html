How Requests Work
  1. You submit a request with the session and reason.
  2. The admin reviews the request in the inbox.
  3. If approved, the system runs a repair operation using the constraint solver.
  4. The solver finds the minimal change that satisfies all mandatory rules.
  5. A new timetable version is generated and published.
  6. You are notified of the outcome.
ℹ The repair solver is planned for a future phase. Step 3–5 are not yet implemented.
What You Can Request
Reschedule Move a session to a different time. Admin and solver will find a compatible slot.
Substitution Request another qualified teacher to cover your session.
Cancellation Cancel a session. Admin decides if a make-up is needed.

Future ML Query Service

In a future phase, this interface will route queries to dedicated problem-solving ML models. The planned routing:

  • Timetable lookups → Deterministic database query
  • Slot/room availability → Constraint engine query
  • Conflict explanations → Validator + explanation module
  • Natural language → LLM parses intent → routes to service
  • Complex scheduling → Problem-solving ML model
⛔ The LLM gateway must not place sessions, validate timetables, or override scheduling constraints. These are performed exclusively by the CP-SAT solver and independent validator.
